# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — native HTML elements only (RESEARCH.md: `<details>`/`<summary>` preferred over Bits UI or Melt UI) |
| Icon library | none — text labels and HTML symbols only in v1 |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tag gaps (`gap-1`), inline badge padding (`px-2 py-1`) |
| sm | 8px | Compact element spacing, tight stacks (`space-y-2`) |
| md | 16px | Default element spacing (`p-4`) |
| lg | 24px | Card body padding (`p-6`), section padding, grid gap (`gap-6` = 24px) |
| xl | 32px | Layout gaps, page section breaks |
| 2xl | 48px | Major section separation |
| 3xl | 64px | Page-level vertical spacing |

Exceptions:
- Filter bar and pagination controls: minimum touch target height 44px for interactive elements (`py-2 px-3` on buttons (~40px height); `min-h-[44px]` ensures touch target compliance on tablet per UI-01).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (text-base) | 400 (normal) | 1.5 |
| Label / Meta | 12px (text-xs) | 400 (normal) | 1.4 |
| Card title / Section heading | 18px (text-lg) | 600 (semibold) | 1.3 |
| Page heading (h1) | 30px (text-3xl) | 600 (semibold) | 1.2 |

Notes:
- Source: RESEARCH.md AgentCard uses `text-lg font-semibold` for card titles, `text-xs` for tags/badges, and `text-3xl font-semibold` for the detail page h1.
- Card summary text uses `text-base text-gray-600` (16px body role) — no separate small/secondary size.
- Exactly 2 declared weights: **400 (normal)** for all body and meta text; **600 (semibold)** for all headings including h1. `font-bold` (700) is not used anywhere in this phase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` / Tailwind `white` + `gray-50` | Page background, card backgrounds, main surfaces |
| Secondary (30%) | `#f9fafb` / Tailwind `gray-100` | Filter bar background, pagination row, nav/header bar, tag chip background |
| Accent (10%) | `#4f46e5` / Tailwind `indigo-600` | Specific elements only — see below |
| Destructive | not applicable | No destructive actions in Phase 2 |

Accent (`indigo-600`) reserved for:
1. Category label on AgentCard (e.g., "Natural Language Processing")
2. GitHub link text on agent detail page ("View on GitHub")
3. Active/selected filter state indicator (active filter button border or text)
4. Pagination button focus ring

Secondary semantic colors (status badges — not accent):
- Production badge: `bg-green-100 text-green-800`
- Beta badge: `bg-yellow-100 text-yellow-800`
- Experimental badge: `bg-gray-100 text-gray-600`

Source: RESEARCH.md AgentCard component example uses these exact Tailwind classes. Status badge colors are semantic (data-driven), not UI accent — they are excluded from the 10% accent budget.

Border color: `border-gray-200` for cards and filter inputs. Use `gray-700` for TechAccordion summary text.

## Interaction Contract

### AgentCard
- Entire card is a block `<a>` tag — full-card click target.
- Card body padding: `p-6` (24px).
- Hover state: `hover:shadow-md transition-shadow` (source: RESEARCH.md).
- Focus state: `focus-visible:ring-2 focus-visible:ring-indigo-600 focus-visible:ring-offset-2` — keyboard navigable.
- Tags: show first 3 only (`agent.tags.slice(0, 3)`) — no overflow indicator in v1.

### FilterBar
- Select dropdowns for category and LLM (from server-loaded distinct values).
- Filter changes update `$derived.by()` list immediately — no submit button needed for client-side filter.
- `goto()` called with `replaceState: true` on filter change for URL shareability (source: RESEARCH.md Pattern 4).
- "Clear filters" text button appears only when at least one filter is active; uses `text-indigo-600` color.

### TechAccordion (DETL-02)
- Uses native `<details>` / `<summary>` — collapsed by default (no `open` attribute).
- `<summary>` text: "Technical Specification" — `cursor-pointer font-semibold text-gray-700 py-3 select-none`.
- No animation in v1 — native browser disclosure behavior only.
- Keyboard: native — space/enter opens, no JS needed.

### CustomizationPanel (DETL-03)
- Rendered as a static list of tailorable fields (constant `TAILORABLE_FIELDS` array).
- v1 fields: `llm.name`, `llm.temperature`, `systemPrompt`, `tools` (source: RESEARCH.md Open Question 2 resolution).
- Each item is a read-only label with a padlock icon substitute (text label "Customizable") — no interactive state in Phase 2.
- Panel heading: "Customization Options" — `font-semibold text-gray-900`.

### Pagination
- Previous / Next buttons with disabled state (`disabled:opacity-40`).
- Page indicator: "Page N of M" — `text-base text-gray-600`.
- Page size: 24 agents per page (source: RESEARCH.md `PAGE_SIZE = 24`).

## Accessibility Contract

- All interactive elements have visible focus rings (`focus-visible:ring-2`).
- `<details>`/`<summary>` for TechAccordion is keyboard accessible by default.
- AgentCard `<a>` elements have descriptive `aria-label` if title alone is ambiguous: `aria-label="{agent.title} — view agent details"`.
- Status badges are decorative; maturity information is also present in text — no `aria-label` needed.
- FilterBar selects have associated `<label>` elements with `for` attributes.
- Images: none used in v1 — no `alt` attributes needed.
