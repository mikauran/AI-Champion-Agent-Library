CLI structure mirrors scripts/generate-mcp.ts (read it first): exported `runCli(argv: string[], io: CliIo): Promise<number>` with injectable io (writeFile, log, error, mkdir, now) and a `main` guarded by an `import.meta.url` check so the test imports it without running. Usage string: `npm run mcp-test -- --subject <fake:good|generator:openapi|cmd:"python3 /path/server.py"> [--case ID ...] [--reruns 1-3] [--format text|markdown|json] [--out report.json] [--allow-local-exec] [--env-base-url NAME] [--env-api-key NAME] [--list]`.
Driver request contract (SHARED LITERALLY with plan 15-11, which builds it; 15-13 cross-checks both):
```ts
// DriverRequest (JSON at <in>/request.json)
{ v: 1,
  subject: { kind: 'staged'; command: 'python3' | 'node'; args: string[] /* relative paths, no '..', <= 8 */; cwd: string /* must be '/work/pkg' or start with '/work/pkg/' (root overridable via MCPTEST_PKG_ROOT for tests) */; id: string /* label for the report, e.g. generator:openapi */; binding?: Record<string,{tool:string;args?:Record<string,unknown>}>; envNames?: {baseUrl?:string;apiKey?:string;baseUrlB?:string} }
       | { kind: 'fake'; variant: string },
  cases?: string[]  /* case ids, <= 12 */, reruns?: 1|2|3 }
```
Driver output: `<out>/report.json` (mcptest-report/1) only. Exit code 0 even when the verdict is not PASS (the report carries the verdict); non-zero only if the request is invalid (then it writes `<out>/error.json` {error: short string}).
</interfaces>
