LVI-INFO Read-API as the hand-authored server calls it (httpx, `apiKey` as a query parameter, base from LVI_API_BASE): GET /api/v1/products/full-data with query lviNumber, supplierNumber, businessID, productType, isActive, page, pageSize (1..1000) returning `{ page, totalResults, totalPages, products: [...] }`; GET /api/v1/products/full-data/{productLinkNumber} returning one product or 404; GET /api/v1/products/full-data/gtin/{gtin} one product or 404; GET /api/v1/products/meta/suppliers a list; GET /api/v1/products/changed a list. Wrong key gives 403. Product fields kept by the server's projection: TT020 (LVI number), TT024 (product link number), TT110 (brand), TT200 (name), TT201 (model), TT052 (GTIN), TT060 (ETIM class id), TT025 (product group), plus etimFeatureValues [{ etimClassId, etimFeatureId, value }]. The server tools return `{ found, product }` (lookups) or `{ products, totalResults, ... , reason? }` (search/filter) with `reason` text on a miss.
Proxy and extension tools: plan 36-02 and 36-03 (lookup_by_lvi_number{lvi_number}, get_product_by_link{product_link_number}, get_product_by_gtin{gtin}, search_products{supplier_number,lvi_number,business_id,product_type,is_active,page,page_size}, filter_by_etim_class{etim_class_id,etim_feature_id,supplier_number,lvi_number,business_id,max_pages}).
Run mode (Option B of docs/tryitout-live-run.md, needed because the stdio or loopback upstream lives on the host and the app must run on the host): app on the host with `LOCAL_MCP_AGENTS=on`, `PI_RUNNER_NETWORK=podman PI_RUNNER_ALLOW_OPEN_EGRESS=true PI_LLM_PROXY_URL=http://host.containers.internal:5173/api/llm/v1` (the registry derives the proxy URL `http://host.containers.internal:5173/api/local-mcp/v1`), `LOCAL_MCP_LVI_URL=http://127.0.0.1:8765/mcp`.
