Route and Pi-integration evidence gathered while planning (write it into the decisions, Task 1):
- Network guard (src/lib/server/tryitout/runtimeDockerode.ts ensureNetwork, lines 143-175): the runner refuses any network that is not `internal` unless PI_RUNNER_ALLOW_OPEN_EGRESS=true. Compose (podman-compose.yml) already puts the app on `aic-pi-internal` (internal: true) with alias `aic-agent-library`; Pi containers reach only that alias (PI_LLM_PROXY_URL=http://aic-agent-library:3000/api/llm/v1). buildCreateOptions never publishes ports or mounts. An app-side proxy on the SAME host:port therefore needs no change to the guard, the compose file, the Containerfile or RunnerConfig.
- A sidecar would need a new compose service that is on `aic-pi-internal` (so the Pi container can reach it) AND on a network with egress (the LVI API), i.e. a dual-homed container bridging the internal network (that is exactly what the guard exists to prevent), plus a python image, the key inside a container (audit option D con) and a second container per run on a 3.7 GB machine.
- Key never enters containers: Pi containers carry only AIC_LLM_TOKEN (leaseManager.ts line 161, per-lease token from llmProxy.registerLeaseToken). The proxy reuses that token via authenticateBearer.
- Auth hook (src/hooks.server.ts): PUBLIC_PREFIXES = ['/api/llm/'] only; an MCP route outside that prefix would get 401 for the container. The new prefix is added to PUBLIC_PREFIXES ONLY when the flag is on, so flag-off behaviour (401 on /api/local-mcp/*) stays identical.
- Pi docs (npm @earendil-works/pi-coding-agent@1.0.4, docs/mcp.md, docs/extensions.md, docs/cli.md, read as untrusted data): Pi 1.0.4 DOES have a built-in MCP client (stdio and streamable HTTP, tools named mcp__server__tool) and extensions (TypeScript, jiti, `pi -e <path>`, `pi.registerTool`, explicit `-e` paths still load under `--no-extensions`). The audit statement "no MCP client" is outdated; the runner passes `--no-extensions --no-mcp` (piRunner.ts buildPiArgs). Option (a) native MCP would make the app implement an MCP streamable-HTTP SERVER endpoint, write mcp.json, drop `--no-mcp`, and expose codemode, OAuth and resource tools. Option (b) a staged extension registering 4 plain tools that POST JSON to the proxy keeps `--no-mcp` and `--no-extensions`, adds one `-e` path and the tool names to `--tools`, and needs a plain REST proxy. (b) chosen. Bash+curl rejected (widens the container surface).
- Upstream (app to LVI-INFO server): local only. stdio subprocess (dev app on the host; server.py from ~/projects/mcp-gen-comparison/arms/handauthored, FastMCP 3.x is installed on the host) or streamable HTTP via `fastmcp run server.py --transport http` on 127.0.0.1. The app image never gains python.
