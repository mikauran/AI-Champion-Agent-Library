<objective>
Make the Try It Out data durable across ingestion: new rows get safe defaults, and re-running ingestion never overwrites a manually-set value. Then get human eyes on all three rendered modes in a real browser.

Purpose: `try_it_out` is not sourced from Oracle AgentSpec YAML (D-05), so the DB is the system of record. Ingestion must be a no-op for these three columns or the example agent (and every future manual value) would be wiped on the next `npm run dev`.
Output: Updated `flattenRecord()` + `onConflictDoUpdate` semantics in `scripts/ingest.ts`, two new regression tests in `scripts/ingest.test.ts`, and a human-verified detail page.
</objective>

<interfaces>
Current shape of the code being changed (`scripts/ingest.ts`):

```ts
function flattenRecord(record: AgentRecord): NewAgentRow {
  return { slug: record.slug, /* ... */ specId: record.specId, lastIngestedAt: new Date().toISOString() }
}
// ...
.onConflictDoUpdate({ target: agents.slug, set: { title: sql`excluded.title`, /* ...every other column... */ } })
```

`scripts/ingest.test.ts` pre-creates the table itself with a hardcoded `CREATE_TABLE_SQL` (so the test does not need `drizzle-kit push`). That literal SQL must mirror `drizzle/schema.ts` or inserts that mention the new columns will fail with "table agents has no column named try_it_out_mode" — and `ingest()` swallows per-file errors, so the symptom would be `succeeded: 0, failed: 3` rather than a crash.

Columns added in plan 01 (`drizzle/schema.ts`): `try_it_out_mode TEXT NOT NULL DEFAULT 'none'`, `try_it_out_url TEXT`, `try_it_out_task_template TEXT`.

Environment facts: no `sqlite3` CLI — use `node -e` with `better-sqlite3`. `npm run build` = `db:push && ingest && vite build` and takes ~30s; it was confirmed working during planning.
</interfaces>
