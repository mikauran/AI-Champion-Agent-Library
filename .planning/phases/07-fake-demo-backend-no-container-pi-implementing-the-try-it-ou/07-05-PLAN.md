<threat_model>
ASVS Level 1. Block on: high severity.

| # | Threat | Severity | Mitigation (implemented and verified in this plan) |
|---|---|---|---|
| T5-1 | **Attacker-supplied `?job=` value reaching the network layer or the DOM** — a crafted URL like `?job=<img src=x onerror=...>` or `?job=../../etc/passwd`. | **high** | `readJobIdFromUrl()` returns a value only if it matches the RFC-4122 UUID regex, otherwise `null`. Non-matching values are discarded client-side and the param is cleared, so nothing malformed reaches `subscribeProgress`, the URL path, or the DOM. Server-side, plan 07-04's routes independently re-validate with `isValidJobId` and 404 — defense in depth, not a single client-side check. Verified by tests feeding script-tag, traversal, and overlong values. |
| T5-2 | **IDOR — guessing another user's jobId to read their triage output.** | medium | jobIds are `crypto.randomUUID()` v4 (122 bits of entropy), so enumeration is infeasible. Accepted residual: anyone holding the URL can fetch the artifact — which is the intended shareability behavior of D-10, on a closed internal demo with non-sensitive input. Documented here rather than mitigated; revisit if this endpoint ever becomes publicly reachable or handles real project data. |
| T5-3 | **Sensitive content in a shared URL** — the URL is bookmarkable and may end up in logs, chat history, or a screen share, granting artifact access to anyone who sees it. | medium | Only an opaque UUID is placed in the URL — never the task text, the filename, or any result content. Users are told in the checkpoint script that the URL grants access to the result, so sharing is an informed act. |
| T5-4 | **Router conflict from direct history manipulation** — calling `history.replaceState` directly conflicts with SvelteKit's router. | low | `writeJobIdToUrl` uses `replaceState` from `$app/navigation` when a SvelteKit router is present, wrapped in try/catch so standalone/test rendering degrades to a no-op rather than throwing. Reads always use `window.location.search`, which is safe in every context. |
| T5-5 | **XSS via restored state rendered in the feed or error block.** | low | Unchanged from Phase 6: the panel renders `{event.summary}` and `{error}` as text, and the `{@html}` prohibition is enforced by the guard test that must pass unmodified. Restored values arrive as JSON from the status route and are rendered through the same text path. |
| T5-6 | **Live-run cost/quota abuse during verification.** | low | The checkpoint script runs a bounded number of manual jobs, each capped at 200 KB of input by plan 07-04's `MAX_UPLOAD_BYTES`. |

No unmitigated high-severity threats.
</threat_model>
