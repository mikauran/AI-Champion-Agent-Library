<threat_model>
ASVS Level 1. Block on: high severity.

| # | Threat | Severity | Mitigation (implemented and verified in this plan) |
|---|---|---|---|
| T3-1 | **Path traversal via the client-supplied upload filename.** `File.name` can be `../../../../etc/cron.d/x` or `..\\..\\x`. RESEARCH.md's Pattern 3 example joins `inputDir(jobId)` with `job.fileName` — writing/reading that path escapes the working directory. | **high** | The client filename is NEVER used as a path component. The upload is always written to the fixed server-chosen path `inputFilePath(jobId)` = `.tryitout-work/<jobId>/input/input.txt`. `JobRecord.fileName` retains the original name for display/logging only and is never passed to `join()`. Verified by a test that submits a `File` named `../../escape.txt` and asserts the bytes land at `input/input.txt` with nothing written outside `workDir(jobId)`. |
| T3-2 | **Path traversal via `agentId`.** `agentId` arrives from the client and is joined into `data/tryitout-prompts/<agentId>/skill.md`, so `../../../.env` would read arbitrary files off disk. | **high** | `AgentIdSchema` (Zod) enforces `/^[a-z0-9]+(-[a-z0-9]+)*$/` with a max length of 64 BEFORE any `join()`. Additionally the agent row must exist in the DB, so only ingested slugs resolve. Verified by tests asserting `loadPromptFor('../../../etc/passwd')` and `loadPromptFor('a/b')` both reject without touching the filesystem. |
| T3-3 | **Path traversal via `jobId`** when routes later pass `params.id` into path helpers. | **high** | `isValidJobId(id)` enforces the RFC-4122 UUID shape `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i` and every path helper calls it and throws on a miss, so a bad id can never reach `join()`. `getJob` additionally requires an exact `Map` key hit. Verified by a test asserting `outputFilePath('../etc')` throws. |
| T3-4 | **API key exposure to the client (SC-09).** | **high** | All three modules live under `src/lib/server/`, which SvelteKit's bundler refuses to include in client output. The OpenAI client is constructed lazily inside `runJob`, so nothing reads the key at import time. Verified by a grep asserting `OPENAI_API_KEY` appears in no client-reachable file. |
| T3-5 | **Prompt injection from uploaded content** — the RFI text is attacker-controlled and could instruct the model to ignore the skill and emit something else. | medium | Accepted for a closed internal demo, with reduction: `composePrompt` places the untrusted input LAST behind an explicit delimiter line marking it as data to be classified, never as instructions, and the base prompt (07-02) states the model must not claim to have accessed systems it did not. Blast radius is one text file in a per-job directory; there are no tools, no network egress, and no persistence beyond that file. |
| T3-6 | **Unbounded resource use** — a huge upload blows up the model context and fills the disk. | medium | A 200 KB cap (RESEARCH.md Open Questions §3) is enforced in the POST handler (plan 07-04) before any disk write. This plan additionally truncates defensively: `composePrompt` caps the embedded input text at 200 000 characters so a store populated by any other path still cannot produce an unbounded request. |
| T3-7 | **Unbounded memory growth** — the job `Map` never evicts, so a long-lived demo server accumulates job records and their event arrays. | low | Accepted for a single-process demo (state is intentionally lost on restart per RESEARCH.md Pitfall 2). Bounded in practice by manual demo usage. Documented in the module header rather than solved. |

No unmitigated high-severity threats.

<flagged_assumptions>
Derived from the spec-less edge probe (all 9 SCs returned `unresolved`; the planner resolved them into concrete `must_haves.truths` above). Assumptions worth surfacing explicitly:

- **A-1 (concurrency, SC-02/SC-04):** Isolation is by UUID-prefixed directory only. Two concurrent jobs are safe because they never share a path or a `Map` entry, but nothing serializes them and nothing bounds total concurrency. This is the ROADMAP's stated accepted risk ("file-collision risk is knowingly accepted for the demo"), not an oversight.
- **A-2 (interruption, SC-04):** If the process dies mid-run, the job is lost entirely — the `Map` is not persisted (RESEARCH.md Pitfall 2). A subsequent status poll returns 404, which plan 07-05 surfaces as a clean return-to-idle rather than a failure. No resume semantics are implemented or claimed.
- **A-3 (SC-04 status granularity):** `queued` exists only between `createJob` (in the POST handler) and the first line of `runJob`. It is a real state the client can observe because the POST response returns before the runner is awaited, but it is short-lived by design.
</flagged_assumptions>
