# Phase 06 — UI Design Contract

> Visual and interaction contract for `TryItOutPanel.svelte` and its wiring into the agent detail page's `runnable` mode. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — not applicable. This is a Svelte 5 / SvelteKit project; shadcn is a React-only tool. Confirmed by 06-CONTEXT.md `code_context`: "plain Tailwind utility classes, no external UI library." No `components.json` found in repo. |
| Preset | not applicable |
| Component library | none — plain Tailwind utility classes (Tailwind v4, `@import "tailwindcss"` in `src/app.css`, no `tailwind.config.*` needed) |

| Font | Tailwind default sans-serif stack (no custom `font-family` declared anywhere in the codebase). Progress feed uses `font-mono` (Tailwind's default monospace stack) to read as an authentic tool-call log per CONTEXT.md D-05/"Specific Ideas". |

## Spacing Scale

Declared values (must be multiples of 4) — reused verbatim from existing site-wide usage (`AgentCard.svelte`, `CustomizationPanel.svelte`, `+page.svelte`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-free inline gaps (`gap-1`), feed-line vertical rhythm (`py-1`) |
| sm | 8px | Compact element spacing (`gap-2`, `mb-2`), badge padding |
| md | 16px | Default element spacing (`gap-4`, form field vertical gap) |
| lg | 24px | Panel container padding (`p-6`, matches `CustomizationPanel.svelte` aside) |
| xl | 32px | Layout gaps between major panel sections (if standalone page wraps it) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions: none new for this phase. (Existing codebase has a pre-existing `py-0.5` (2px) micro-exception for status badges/tags — e.g. `AgentCard.svelte`'s `Production`/`Beta` pills — but `TryItOutPanel.svelte` introduces no new badges and does not need to repeat this exception.)

## Typography

Reused verbatim from the existing site-wide scale (`+page.svelte` h1, `AgentCard.svelte` card title, body/meta text) — no new sizes introduced for this phase.

| Role | Size | Weight | Line Height | Usage in this phase |
|------|------|--------|-------------|-------|
| Body | 14px (`text-sm`) | 400 regular | 1.5 | Task textarea content, event `summary` lines in the progress feed, error body copy |
| Label | 12px (`text-xs`) | 600 semibold (`font-semibold`) | 1.4 | Field labels ("Task", "Attach a file (optional)"), event timestamps, "Progress" section label, "Job failed" heading |
| Heading | 18px (`text-lg`) | 600 semibold | 1.2 | Reserved token, matches `AgentCard.svelte` title scale — not required inside the embedded panel (the detail page's own h1/"Try it out" affordance already provides context); use only if the standalone dev-route wrapper needs its own page heading |
| Display | 30px (`text-3xl`) | 600 semibold | 1.2 | Reserved token for consistency with `agent.title` h1 on the detail page — not rendered by the panel itself |

Two weights total: 400 (regular, body/input text) and 600 (semibold, labels/headings). No third weight introduced.

## Color

60/30/10 split reused from the existing site palette (`+layout.svelte`, `AgentCard.svelte`, `CustomizationPanel.svelte`) — no new base colors introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`bg-white`) | Page background, panel container background |
| Secondary (30%) | `#f9fafb`/`#f3f4f6` (`bg-gray-50`/`bg-gray-100`), border `#e5e7eb` (`border-gray-200`) | Panel container border, progress feed log box background, textarea/file-input border, disabled-state background |
| Accent (10%) | `#4f46e5` (`indigo-600`) | "Run" button background, "Download results" button background, `focus-visible` ring on textarea/file input/buttons (matches existing `focus-visible:ring-2 focus-visible:ring-indigo-600` pattern from `AgentCard.svelte`) |
| Destructive/semantic | `#fef2f2` bg / `#fecaca` border / `#b91c1c` text (`bg-red-50` / `border-red-200` / `text-red-700`) | Failed-state block only — background, border, and error text |

Accent reserved for (explicit list, never "all interactive elements"):
- "Run" button background (primary CTA)
- "Download results" button background (shown only on `succeeded`)
- `focus-visible` ring on the textarea, file input, and both buttons

Accent is explicitly NOT used for: progress feed timestamps or event text (stays `text-gray-500`/`text-gray-900` per body/label roles), the failed-state block (uses red, not indigo), or any status text — this keeps the single indigo accent restrained to the two primary actions, consistent with its existing site-wide role as the one interactive-affordance color (links, category label, focus rings).

No new success/green badge is introduced for the `succeeded` state — the appearance of the "Download results" button IS the success signal. Adding a third semantic color (green) for "succeeded" was considered and rejected to keep the accent budget disciplined (destructive red is the only second semantic color, reserved for `failed` only, per template rule).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (idle) | "Run" (label locked by 06-CONTEXT.md D-10) |
| Primary CTA (in-flight) | "Running…" — button disabled while `status` is `queued` or `running`, so the user gets feedback that a job is in progress |
| Secondary CTA | "Download results" (label locked by D-10; rendered only when `status === 'succeeded'`) |
| Task textarea label | "Task" |
| Task textarea placeholder | "Describe the task you want this agent to do…" |
| File input label | "Attach a file (optional)" |
| Progress feed section label | "Progress" (small `text-xs font-semibold text-gray-500 uppercase tracking-wide` label above the auto-scrolling log — matches the existing meta-label visual weight used for badges/tags) |
| Empty state | Not applicable — the progress feed section does not render at all until `submitJob` is called; the pre-run view is just the form (task textarea + file input + Run button), so no "no data yet" copy is needed |
| Error state heading | "Job failed" |
| Error state body | Renders the raw `JobUpdate.error` string verbatim (e.g. `"pi exited non-zero: required input file missing"`, per D-06/mock), followed by a static next-step line: "Adjust your task and try again." |
| Destructive confirmation | None in this phase — Run and Download are non-destructive, idempotent actions (re-running simply starts a new job; no delete/discard/irreversible action exists) |

## UI Considerations

Applicable state considerations resolved: 6 covered, 2 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | progress feed (pre-run) | ✅ covered | Feed section does not render until `submitJob` resolves; the initial view is the form only — no empty-list copy needed (see Copywriting Contract "Empty state" row) |
| loading/populated | progress feed (`queued`→`running`) | ✅ covered | `subscribeProgress` emits `running` immediately then appends timestamped `JobEvent.summary` lines on a timer; each new line appends at the bottom and the feed auto-scrolls to keep the latest visible (D-10) |
| zero-one-many | progress feed events | ✅ covered | Feed renders correctly whether it holds 0 (just started), 1, or many events — simple append-only list, no special-casing needed per event count |
| partial | running job mid-stream | ✅ covered | Run button shows "Running…" and is disabled for the full `queued`→`running` window (see Copywriting Contract "Primary CTA (in-flight)"), distinguishing in-flight from idle/terminal states |
| error | failed job | ✅ covered | Red block renders "Job failed" heading + verbatim `JobUpdate.error` + static next-step copy, per Copywriting Contract |
| populated (terminal) | succeeded job | ✅ covered | "Download results" button (indigo) appears on `succeeded`; no additional green success badge is introduced (see Color section rationale) — the button's appearance is the success signal |
| overflow | progress feed log box | 🧪 backstop | Long event lists must scroll within a bounded-height monospace log box (e.g. `max-h-64 overflow-y-auto`) rather than growing the page indefinitely — verify visually that height is capped and auto-scroll keeps pace with new lines |
| long-text | task textarea input, event `summary` lines | 🧪 backstop | Textarea wraps natively; feed lines must wrap (not clip or force horizontal scroll) inside the monospace log box even for unusually long `summary` strings — verify no horizontal overflow/clipping |
| zero-one-many | file input (select/replace) | ⚠ unresolved | Optional file attachment relies on the native `<input type="file">` single-file replace-on-reselect behavior; no custom "remove selected file" chip/affordance was specified in CONTEXT.md. Planner should treat "native browser default is sufficient, no custom removal UI" as an assumption unless the executor finds it insufficient during implementation. |
