Spike independence: the implementation from plan 01 supports both file-staging variants behind PI_RUNNER_FS_MODE (`tmpfs`: ReadonlyRootfs + tmpfs /work and agent dir; `layer`: writable container layer for /work and agent dir, tmpfs /tmp only). The smoke script decides which one the host supports; nothing in the code depends on the answer. Fallback ladder from RESEARCH Pattern 3, in order: (a) `tmpfs` with putArchive (D-21 preferred); (b) `layer` (drops read-only root, which D-21 allows "if Pi allows it"); (c) if putArchive fails even in `layer`, stop and report: env-generated config files in the container start command would be the next step and needs a new plan.
