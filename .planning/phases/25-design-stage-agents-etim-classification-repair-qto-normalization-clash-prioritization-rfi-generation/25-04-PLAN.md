<objective>
Agent 3, Clash prioritization: reads a clash report exported as CSV text (Navisworks/BCF-like columns), clusters related clashes, ranks them, and drafts a prioritised list for the BIM coordinator, plus a findings table ready to feed the RFI generation agent (Plan 25-05).

Purpose: third design-stage agent through the done bar.
Output: entry, SKILL.md, synthetic sample, runnable flag, live run evidence, gaps and inventory updated.

Execution notes (apply to this plan):
- Run after 25-03 has finished its container run (one container run at a time; no podman during `npm run check`/`vite build`). Edit only this plan's files; shared files get small additive edits.
- Sample data synthetic only, labelled. Every output is a draft for engineer review. Never read `.env`.
- DDC sources (MIT, github.com/datadrivenconstruction/DDC_Skills_for_AI_Agents_in_Construction): `2_DDC_Book/4.3-BIM-Validation-Pipeline/clash-resolution-analyzer` (prioritise by impact, find patterns, assign responsibility by trade, track status) is the best fit; `1_DDC_Toolkit/BIM-Analysis/bim-clash-detection` supplies the clash categories (hard/soft, MEP vs structural). Their SKILL.md files are Python-centred; here the idea is re-expressed as text-only instructions (own design, credited in `metadata.attribution`, the SKILL footer and docs/third-party-notices.md). Do not copy the DDC book text.

Shared findings format (also defined verbatim in Plan 25-05; keep identical):
```
finding_id | clash_ids | priority | disciplines | location | description | suggested_owner | open_question
```
finding_id is `F-01`, `F-02`, ... per cluster; clash_ids a comma list of input ids; priority P1|P2|P3; suggested_owner is a discipline/role, never a person.
