<objective>
Agent 4, RFI generation: turns findings from model checks or clash prioritisation into draft RFIs for the BIM coordinator to review and send. It complements, and does not replace, `rfi-triage-assistant` (conversational drafting/routing of field RFIs) and `demo-rfi-triage` (triage of one uploaded RFI), which stay unchanged.

Purpose: fourth design-stage agent through the done bar.
Output: new entry, SKILL.md, synthetic sample, runnable flag, live run evidence, gaps and inventory updated.

Execution notes (apply to this plan):
- Run after 25-04 has finished its container run (one container run at a time; no podman during `npm run check`/`vite build`). Edit only this plan's files; shared files get small additive edits. This plan does NOT depend on 25-04's output: the sample here is self-contained and only shares the findings table format.
- Sample data synthetic only, labelled. Every output is a draft for engineer review. Never read `.env`.
- DDC source (MIT, github.com/datadrivenconstruction/DDC_Skills_for_AI_Agents_in_Construction): `1_DDC_Toolkit/Document-Control/rfi-management` (RFI numbering, routing to the right party, deadlines, status) gives the RFI field set; its Python tracking/notification parts are out of scope. Own design, credited in `metadata.attribution`, the SKILL footer and docs/third-party-notices.md.

Shared findings format (identical to Plan 25-04):
```
finding_id | clash_ids | priority | disciplines | location | description | suggested_owner | open_question
```
Model-data findings (no clashes) use `-` in clash_ids.
</objective>
