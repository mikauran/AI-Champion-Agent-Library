<objective>
Agent 1, ETIM & classification repair: reads a textual extract of IFC element properties (CSV as text) and a small class/feature excerpt supplied in the same input, and drafts a repair proposal per element (missing, wrong or inconsistent classification), flagging uncertainty.

Purpose: first design-stage agent counted through the done bar (entry + one real-model container run).
Output: catalog entry, SKILL.md, synthetic sample, runnable flag, one live run with evidence, gaps and inventory updated.

Execution notes (apply to this plan):
- Execute one Try It Out container run at a time and never in parallel with another 25-0x plan's run; do not run podman during `npm run check` or `vite build`. Edit only the files in this plan's `files_modified`; for shared files (set-try-it-out-mode.ts, inventory, gaps, third-party-notices, 25-VERIFICATION, 25-HUMAN-UAT, spend-log) make small additive edits (one list entry, one row, one section) so sequential plans merge cleanly.
- Sample data is synthetic only, labelled. Every output is a draft for engineer review. Never read `.env`.
- DDC skill used as a source of ideas: `1_DDC_Toolkit/BIM-Analysis/bim-classification-ai` (MIT, github.com/datadrivenconstruction/DDC_Skills_for_AI_Agents_in_Construction): its approach of analysing element name/type/properties to suggest a code with a confidence. It covers UniFormat/MasterFormat/OmniClass, NOT ETIM, and its SKILL.md is Python-code-centred; the instructions here are an own design adapted to ETIM-style class/feature mapping on text input. Credit it in `metadata.attribution`, in the SKILL.md footer and in docs/third-party-notices.md. No ETIM skill exists in the DDC repository (checked via the GitHub tree 2026-10-14).
</objective>
